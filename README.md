# Komek — маркетплейс услуг по уходу

Платформа поиска и найма проверенных исполнителей услуг по уходу: няни, бебиситтеры,
сиделки, компаньоны для пожилых. ТЗ: [docs/tz-care-marketplace.md](docs/tz-care-marketplace.md).

## Структура

| Директория | Что это | Стек |
|---|---|---|
| `backend/` | REST API, доменная модель, миграции | Python 3.12, FastAPI, SQLAlchemy 2 (async), PostgreSQL, Alembic |
| `mobile/` | Мобильное приложение (приоритет №1) | React Native (Expo), TypeScript, React Native Paper |
| `web/` | Веб-админка модератора (SEO-каталог — позже) | Next.js (App Router, TS) |
| `docs/` | ТЗ и проектные документы | |

## Backend: быстрый старт

```bash
cd backend
python -m venv .venv
.venv\Scripts\pip install -e ".[dev]"
copy .env.example .env
# поднимите PostgreSQL (docker compose up -d db) и примените миграции:
.venv\Scripts\alembic upgrade head
.venv\Scripts\python -m app.db.seed
.venv\Scripts\uvicorn app.main:app --reload
```

Swagger: http://localhost:8000/docs

Тесты и линт (БД не нужна — тесты на SQLite in-memory):

```bash
cd backend
.venv\Scripts\python -m pytest tests -q
.venv\Scripts\python -m ruff check app tests
```

В `local`/`staging` SMS не отправляются: код входа фиксированный (`OTP_DEBUG_CODE`,
по умолчанию `111111`) и возвращается в ответе `POST /auth/otp/request` полем `debug_code`.

## Что уже реализовано (backend MVP)

- Вход по SMS-коду (OTP → JWT-пара), refresh-токены.
- Доменная модель: пользователи и согласия (ПДн РК), профили исполнителей,
  каталог услуг двух вертикалей («Дети», «Пожилые»), гео Астаны, верификация
  (уровни 0–3, документы, интервью, журнал доступа), заказы со стейт-машиной,
  отклики, чат (модель), платежи/выплаты (модель), отзывы, жалобы, аудит.
- Поиск исполнителей с фильтрами: услуга, район, цена, уровень верификации,
  языки, квалификации, срочность.
- Два сценария найма: каталог (прямой заказ) и заявка (биржа откликов).
- Жизненный цикл заказа: черновик → опубликован → принят → подтверждён →
  чек-ин → чек-аут (расчёт фактических часов и комиссии) → оплата.
- Отзывы: только по оплаченным заказам, окно 14 дней, низкие оценки — в модерацию.
- Чат: диалоги заказчик↔исполнитель, маскировка контактов до оплаты (антидизинтермедиация),
  разблокировка после оплаченного заказа между парой.
- Модерация: заявки на верификацию (подача → решение модератора → активация анкеты),
  жалобы (категория «безопасность» автоматически приостанавливает профиль), аудит-лог.
- Сид справочников: услуги MVP, квалификации, Астана + районы (`python -m app.db.seed`).

## Модель монетизации (текущая)

**Бесплатная**: комиссия 0, платформа не проводит платежи — заказчик рассчитывается
с исполнителем напрямую. После чек-аута заказ автоматически считается оплаченным
(это открывает отзывы и контакты в чате). Эквайринг и комиссия — отдельный этап,
доменная модель платежей уже заложена.

## Операционка (ТЗ 5.3, 5.5–5.7)

- **Отмены со штрафами**: правила «часов до начала → % штрафа» настраиваются админом
  (`PUT /admin/cancellation-rules`), дефолт: <4ч — 50%, <24ч — 20%.
- **Реестры выплат**: `POST /admin/payouts/build` группирует оплаченные заказы по
  исполнителям (минус комиссия 15%); отметка «выплачено» — вручную до эквайринга.
- **Модерация отзывов**: оценки 1–2 в очереди `/admin/reviews`, публикация пересчитывает рейтинг.
- **Аналитика**: `GET /admin/stats` — воронка заказов, GMV, комиссия, уровни исполнителей.
- **Календарь занятости**: `GET/PUT /providers/me/schedule` + экран «График» в мобилке.
- **Тарифы и промокоды**: ставки комиссии (глобальные и по категориям, с датами действия)
  применяются при создании заказа; промокоды с процентом/суммой скидки.
- **Избранное**: `GET /providers/favorites` + фильтр «Избранные» в поиске мобилки.
- **SMS**: шлюз с логом в dev и HTTP-провайдером в проде; фолбэк на критические события
  (принятие заказа, подтверждение найма), если у пользователя нет устройства для пуша.
- **Чат с вложениями**: фото и голосовые, файлы в медиа-бакете (отдельно от документов),
  скачивание только участниками диалога; подпись к фото тоже маскируется до оплаты.
- **Проверка личности**: интерфейс KYC-провайдера (Verigram или аналог) с dev-заглушкой.
  Заказчику даёт значок «проверенный», исполнителю — уровень 1 и ИИН для сверки со справками.
  В production с незаполненным `KYC_API_URL` эндпоинт отвечает 503, а не подтверждает вслепую.
- **Инструкция eGov**: экран с пошаговым получением справок, диплинком в eGov mobile
  и явным согласием на обработку ПДн перед загрузкой.
- Веб-админка: Дашборд / Верификация / Жалобы / Отзывы / Финансы / Настройки.

## Дополнительно реализовано

- Загрузка документов верификации (multipart, ≤15 МБ, JPEG/PNG/WebP/PDF):
  локальное хранилище в dev, S3-совместимое в проде; решения модератора по документам,
  журнал каждого доступа к файлу (закон о ПДн).
- Пуш-уведомления через Expo Push: регистрация устройств, триггеры — новый заказ,
  отклик, принятие, сообщение чата, решение по верификации.
- Назначение модератора: `python -m app.db.make_staff +7701... moderator`

## Платежи

Контур написан провайдер-агностично — подробности в
[docs/payments-integration.md](docs/payments-integration.md):
холд при подтверждении заказа → списание фактической суммы после чек-аута →
возврат излишка; при отмене заказчиком возврат за вычетом штрафа, при отмене
исполнителем — полный. Вебхуки эквайера с HMAC-подписью, защитой от replay
и идемпотентностью по `event_id`. Сверка расхождений — в админке.

Без `PAYMENT_API_URL` работает песочница; **в production она запрещена** —
иначе заказы оказались бы бесплатными.

## Карты и адреса (2GIS)

Подробности — [docs/2gis-integration.md](docs/2gis-integration.md). Карта в приложении
на MapGL внутри WebView (официального RN SDK у 2GIS нет), подсказки адресов и
геокодинг — через наш бэкенд, чтобы ключ Catalog API не попадал в клиент.
Без ключей работает режим разработки с честной заглушкой вместо карты.

## Ключевые «заглушки» (контракты есть, ключей нет)

- Эквайринг (Kaspi Pay / банк): песочница, подключение = заполнить `.env`.
- KYC (liveness + удостоверение): заглушка, в production отвечает 503.
- SMS-шлюз: в local пишет в лог, код входа фиксированный.
- 2GIS: без ключей карта-заглушка, геокодинг отдаёт центр города.
- Автопроверка справок eGov по QR: пока ручная модерация по номеру.
- Чеки ОФД: поля заведены, отправка зависит от юридической схемы.
