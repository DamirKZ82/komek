# Подключение 2GIS

По ТЗ (п. 6) карты и геокодинг — на 2GIS как приоритетном провайдере для Казахстана.
Используются два продукта с **разными ключами**:

| Ключ | Что делает | Где живёт |
|---|---|---|
| `DGIS_MAP_KEY` | MapGL JS API — отрисовка карты | Отдаётся приложению через `GET /geo/config` |
| `DGIS_CATALOG_KEY` | Catalog API — подсказки адресов и геокодинг | **Только на сервере** |

Ключ MapGL публичен по своей природе: он попадает в клиент и его видно в трафике.
Ограничивать его нужно в Platform Manager (домен/пакет приложения). Ключ Catalog API
в клиент не попадает — приложение ходит через наши эндпоинты `/geo/*`, поэтому вытащить
его из APK нельзя.

Без ключей всё работает в режиме разработки: карта показывает надпись
«Карта недоступна», подсказки пусты, геокодинг возвращает центр Астаны.

## Эндпоинты

| Метод | Назначение |
|---|---|
| `GET /geo/config` | Ключ MapGL и центр карты по умолчанию (без авторизации) |
| `GET /geo/suggest?q=&lat=&lon=` | Подсказки адресов по мере ввода |
| `GET /geo/geocode?q=` | Адрес → координаты |
| `GET /geo/reverse?lat=&lon=` | Координаты → адрес (точка на карте) |

Под капотом — `https://catalog.api.2gis.com/3.0`: `/items` с `suggest_type=address`
для подсказок и `/items/geocode` для прямого и обратного геокодинга.
Недоступность 2GIS не роняет запрос: возвращается пустой результат, ошибка уходит в лог.

**Внимание к порядку координат:** 2GIS принимает `location=lon,lat` (долгота первая),
а MapGL — `center: [lng, lat]`. В нашем API везде `lat`/`lon` отдельными параметрами,
перестановка происходит в одном месте — `DgisGeoProvider`.

## Карта в мобильном приложении

Официального React Native SDK у 2GIS нет, поэтому карта — это MapGL JS API внутри
WebView ([mobile/src/components/MapView.tsx](../mobile/src/components/MapView.tsx)).
`react-native-webview` не поддерживает web-платформу, поэтому там тот же HTML
рендерится в `iframe` — благодаря этому карту видно и в браузерной версии.

Связь страницы карты с приложением — через сообщения:
`window.ReactNativeWebView.postMessage` на устройстве и `window.parent.postMessage` в вебе.
Типы сообщений: `ready`, `pick` (координаты центра при выборе точки), `marker` (клик по метке),
`error`.

Где используется:

- **Поиск исполнителей** — переключатель «Список / Карта», метки по базовым точкам анкет.
  Точный адрес исполнителя не раскрывается, только базовая точка выезда.
- **Выбор адреса заказа** (`/address/pick`) — подсказки, точка под пином в центре карты,
  обратный геокодинг адреса. Подсказки запрашиваются с задержкой 400 мс: 2GIS
  тарифицирует каждый успешный запрос.

## Тарификация

Биллинг 2GIS считает успешные запросы (HTTP 200). Поэтому:
подсказки идут с дебаунсом, обратный геокодинг — только после остановки карты,
конфиг карты кэшируется на всё время работы приложения.

## Осталось

- Кэш геокодинга на стороне сервера (одинаковые адреса запрашиваются повторно).
- Построение маршрута до адреса заказа (Directions API) — не входит в MVP.
- Подбор исполнителей по расстоянию: сейчас фильтр по районам, радиус выезда
  в анкете есть, но геопоиск по нему не реализован.
